# Esme's Rio, phase 1 (the world) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the farm page's single farm scene with the Rio world: a map of areas that open by farm day, area scenes (outside and inside) in day, rain and night looks driven by Rio's real weather and clock, and her earned stickers placed in the areas, with the earning engine, the 175 stickers and the sticker book unchanged.

**Architecture:** A new `hub/src/rio/` module reads the finished Rio art pack (copied into `hub/src/assets/rio/`) through typed loaders. Pure functions decide which areas are open, which look to show, which scene state to show and which slot each placed sticker sits in; two canvas components (`RioMap`, `AreaView`) draw them. The farm's data layer gains one row kind (`visited:<area>`, for the map's NEW badge); everything else is derived, so no stored data is migrated.

**Tech Stack:** React 18, TypeScript, Vite (import.meta.glob for asset URLs), Dexie, Vitest + Testing Library, Playwright.

**Spec:** `/Users/esme/Documents/coding/esmeworld-notes/rio-design.md` (private notes folder; read "Where the game is today", "The areas", "Nothing is lost", "Opening order", "Weather and night", "For the builder", "Rulings"). Art: `/Users/esme/Documents/coding/esmeworld-notes/art/final/rio-pack/` (each folder has a README describing its files).

**Scope:** phase 1 is the world only. Not in this plan (later plans): the v3 sticker families and their rules (the 87 Rio launch stickers belong to these), per-action reward bundles, ingredients, cooking, recipes, Zona Sul and selling, the clothing store's wardrobe mechanic and the 30 new outfit pieces, the end-of-day summary, holiday events, and the stuck task holding an opening.

## Global Constraints

- Only real tasks and habits move the game; nothing in the game earns anything (ruling 2026-11-14).
- Nothing is ever taken away: every earned, seen or placed sticker stays earned; no existing farm row is rewritten or deleted.
- The earning engine (`farm/earning.ts`, `farm/catalogue.ts`), the 175-sticker collection and the sticker book's pages are unchanged.
- The map never scrolls: the whole map always fits the window, at the largest crisp size that fits (Esme, 2026-11-14: "i dont wanna have to scroll").
- Never choose colour, easing, type, composition or timing (repo CLAUDE.md). Use the pack's art as delivered. Any new UI wording is marked `// PLACEHOLDER WORDING`. Any new motion uses linear easing and the existing motion constants in `farm/motion.ts`.
- Respect `prefers-reduced-motion` (`farm/hooks.ts` `useReducedMotion`): no rain-overlay animation when set.
- The weather request sends only Rio's fixed coordinates; nothing about Esme leaves the device.
- Rio's time zone is `America/Sao_Paulo`.
- Esme's top rule ("never lose answers"): never skip the save and self-test checks; the full unit suite and the farm and sync e2e specs must pass before the branch is pushed.
- Work in the worktree `.claude/worktrees/rio` on branch `rio-phase1` (off `origin/worktree-hub-design-spec`). Push the branch; never merge or deploy (Core merges).
- Asset files only from `rio-pack/**` final folders, never `previews/`, `_scratch/` or any `*REVIEW-ONLY*` file.

## Review Focus

1. **Weather service down or offline:** the map and areas must still show, using Rio's clock for night and no rain. (Task 4 test: fetch rejects → look is from the clock.)
2. **A placed sticker whose area has no art yet or hasn't opened** (orchard, glasshouse, museum, farmhouse): it stays in the book as placed and earned, never disappears or errors. (Task 3 test.)
3. **More placed stickers than an area's slots** (beds 56 + barnyard 12 → fazenda): the extras stay in the book and the area says how many more are in the book. (Task 3 test.)
4. **A sync row of the new `visited` kind arriving at a device still on the old build:** the old `validFarm` rejects it and the old `farmState` ignores it; nothing else breaks. (Task 5 test: the old phase-1 rows still parse alongside visited rows; a visited row with a bad key is rejected.)
5. **A very narrow or very short window:** the map still fits without scrolling (scale may go below 1 device pixel per art pixel only as a last resort, at the smallest whole fraction). (Task 6 test.)

### Task 4: Rio's weather and clock

**Files:**

**Interfaces:**
- Produces:
  - `RIO = { latitude: -22.98, longitude: -43.20, timeZone: "America/Sao_Paulo" }`.
  - `rioHour(now: Date): number` (0–23, Rio time, via `Intl.DateTimeFormat`).
  - `clockLook(now: Date): "day" | "night"`: night from 18:00 until 06:00 Rio time.
  - `RAIN_CODES`: WMO codes 51–67, 80–82, 95–99.
  - `lookFrom(w: { isDay: boolean; code: number } | null, now: Date): Look`: night when `w ? !w.isDay : clockLook(now) === "night"`; else rain when `w && RAIN_CODES.has(w.code)`; else day.
  - `fetchRioWeather(fetchFn = fetch): Promise<{ isDay: boolean; code: number } | null>`: GET `https://api.open-meteo.com/v1/forecast?latitude=-22.98&longitude=-43.2&current=weather_code,is_day&timezone=America%2FSao_Paulo`, 5 s timeout via `AbortController`, null on any failure.
  - `useRioLook(): Look` hook: fetches on mount and every 30 minutes, caches the last result for 30 minutes in `sessionStorage` key `rio-weather` (all access in try/catch), recomputes the clock fallback every minute (`useHour` pattern in `farm/hooks.ts`).

  - `lookFrom({ isDay: true, code: 61 })` is rain; `({ isDay: false, code: 61 })` is night; `({ isDay: true, code: 2 })` is day.
  - `lookFrom(null, <21:30Z>)` is night (Review Focus 1).
  - `fetchRioWeather` with a fetch that rejects returns null; with `{ current: { weather_code: 80, is_day: 1 } }` returns `{ isDay: true, code: 80 }`; the request URL contains only the fixed coordinates.
