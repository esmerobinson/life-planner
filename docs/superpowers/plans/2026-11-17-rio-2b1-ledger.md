# Esme's Rio 2b-1: the reward ledger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every real action pays out ingredients, worked out from her real data, banked each night so nothing is ever lost, plus the stored rows that later plans spend from. No screens yet.

**Architecture:** Pure modules in `hub/src/rio/rewards/` turn her items, habits, journal facts and two kinds of stored fact into **reward events** with stable ids. Each event's **gift** is a deterministic hash pick, and the **ledger** is the union of live events and **bank rows**, by event id. All new state is new kinds in the synced `farm` table (`farm/state.ts`), validated like every farm row. `FarmEngine` exposes `ledger` and `economy` on `FarmView` and writes this device's bank rows for days that have ended. Read the overview's "key decision" first: `2026-11-17-rio-phase2b-overview.md`.

**Tech Stack:** React 18, TypeScript, Dexie, Vitest (+ fake-indexeddb, the `sync/fakeServer.ts` fake), Playwright.

**Spec:** `/Users/esme/Documents/coding/esmeworld-notes/rio-design.md` ("Cooking runs on real tasks", "Several rewards per action", "Nothing is lost"); overview `docs/superpowers/plans/2026-11-17-rio-phase2b-overview.md` (row kinds, event table, decisions).

## Global Constraints

- Only real tasks, habits and journal actions create rewards. Nothing in the game creates any (ruling 2026-11-14).
- Nothing is ever taken away. A banked event stays when its to-do is unticked, archived, deleted or purged. No phase-1 row kind, validator rule or counter changes; `farm/earning.ts` and `farm/catalogue.ts` are untouched.
- Fresh start: only activity on or after the farm's start counts (`clipItems`, as `counters` does).
- Each thing counts once. An event id appears at most once in the ledger, however many devices banked it.
- Journal privacy: rows hold only dates, kinds and item ids, never journal words. Journal events exist only where the journal key is confirmed (`journal !== null`).
- Rows: new kinds only in the `farm` table. Append-only ids are UUIDv7 (`domain/ids.ts` `newId`). A device rewrites only its own `bank` row and only to add events. No Dexie version bump, no server change.
- Every tuning value lives in `hub/src/rio/rewards/tuning.ts`, each line marked `// DEFAULT: Esme to confirm`.
- Gifts only pick ingredients that have art (`hasIcon`). A list with none falls back to its first entry.
- Esme's top rule ("never lose answers"): never skip the save and self-test checks. Before pushing, run `npm test`, `npm run build`, `npx playwright test e2e/farm.spec.ts`, the pwa and phone specs, and `npm run e2e:sync`.
- Work in `.claude/worktrees/rio-2b1` on branch `rio-2b1` (off `rio-menu` with `rio-areas` merged). Push; never merge or deploy.
- Asset files only from final pack folders (`art/final/**`), never `previews/`, `options/` or `_scratch/`.

## Review Focus

1. **A to-do ticked, its reward shown, then unticked the same day:** it leaves the ledger. Ticked on day D and unticked on D+1 after banking: it stays. (Task 6 tests.)
2. **Two devices bank the same day, one with the journal locked:** the ledger holds the union, with every event once, and the check-in gift from the device that had it. (Task 8 two-device test.)
3. **Two devices bank the same event with different gifts** (a tuning change between builds): every device picks the gift from the earliest `(date, device)` row. (Task 5 test.)
4. **Spending more than she has** (two offline devices cook the same beans): `have` shows 0, never negative, and coins never show below 0. (Task 7 property test.)
5. **A backup made before cook/sell rows existed, restored by replace:** those rows go and the ingredients come back. Merge adds only the missing rows, and a damaged `bank` row refuses the whole file. (Task 8 tests.)
